# グローバルルール

出力およびコード内のコメント・Docstring等は日本語で記述してください。

## ソフトウェア・コンポーネント設計原則

- **YAGNI / DRY / KISS / SOLID**: 常にこれらの原則を念頭に置き、過剰な抽象化を避け、シンプルで再利用性の高い設計を心がけてください。
- **アクセシビリティ**: 常にアクセシビリティ（a11y）を考慮したコンポーネント設計を行ってください。

## UX / UI ガイドライン

ユーザー離脱を防ぎ、エンゲージメントを高めるため、以下のUX心理学コンセプトを適用してコードやデザインを提案・実装してください。コードレビューの際もこれらの観点からの改善案を含めてください。

- **認知負荷の低減**: 情報過多を避け、段階的開示（Progressive Disclosure）や視覚的階層（Visual Hierarchy）を用いて直感的な情報整理を行ってください。
- **応答性・フィードバック**: 処理にかかる時間は0.4秒の壁（ドハティの閾値）を意識し、遅延がある場合はローディングUIやスケルトンを適切に配置してください。
- **行動の促進と選択の最適化**: 決断疲れを防ぐために選択肢を絞り、適切なデフォルト値やナッジ（Nudge）を提供してください。
- **美しさと一貫性**: 美的ユーザビリティ効果を意識し、洗練された一貫性のあるUIパターンを採用してください。

## モダンなテスト設計 (Vitest & React Testing Library)

- **振る舞いの検証**: 実装詳細（内部Stateやメソッド）ではなく、ユーザーの振る舞い（DOMの挙動）を検証してください。
- **アクセシビリティ・ファースト**: テストが支援技術の正しさを担保するよう、可能な限り `getByRole` を優先して使用してください。
- **AAAパターン**: Arrange (準備), Act (実行), Assert (検証) の3フェーズでテストを記述してください。テストケース名は日本語で記述します。
